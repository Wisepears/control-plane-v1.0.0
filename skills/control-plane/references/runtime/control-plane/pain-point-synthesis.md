# 痛点综合

## 我的触发词

| 我发的请求 | 执行入口 |
|---|---|
| 把我上面的所有痛点综合起来阐述 | [综合](#综合) |
| 归档痛点「条目」或明确同意本轮归档请求 | [归档](#归档) |
| 整理痛点文档 | [整理](#整理) |

## 按需读取

- 准备归档或整理时，查[Pruning 原文](../skills/mattpocock/writing-for-agents/writing-for-agents.md#pruning)。修改正文后，[核对实际改动](../关于内容维护.md#check-edits)。
- 写入归档时读[归档条目模板](archive-entry.md)。综合时读[痛点文档的更新规则](../../痛点文档.md#更新规则)。

## 综合

从当前会话的用户原话出发，按[产出原则](../communication-core.md#production-principles)综合此前的痛点，按[追加原话](../../ORIGINAL-INTENT.md#u120)写入[痛点文档](../../痛点文档.md)，核对交付正文与追加内容一致。

## 归档

按用户点名或已确认的归档请求定位[痛点原文](../../痛点文档.md)，核对改动和验证结果，再按模板写入[痛点归档](../../痛点归档.md)。核对原文逐字一致，解决办法能追溯到本次变化。原答复的调整按整理入口处理。

## 整理

收到用户主动提出的整理请求后，按控制面处理重复、过时或已经有归档出处的内容。需要从正文移出的已解决条目，按需核对其归档原文与证据，再在正文保留必要的归档引用。交付前核对仍适用的痛点、证据入口和触发规则。
