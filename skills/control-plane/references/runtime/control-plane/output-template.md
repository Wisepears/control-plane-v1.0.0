## 样例来源

本模板取自本地原始材料《我与AI关于原始材料的初步探讨.docx》的 Answer1 和 Answer2。两版都先有词汇表（领域面）、公理定理（问题域）等等要解决的问题，再展开方案、依据和结论。需要把过程讲透时，样例用数据链和测试用例检查读者能否把各部分接起来。

<a id="output-template"></a>
## 输出模板

**开工说明。** 用一两句写出准备查哪项依据、采用内核的哪一步、要解决什么。直接使用「当前目标」「内核工作流程【1】」等本轮触发行动的引导词，根据实际需要选用【2】或【3】。

> 我会先读取当前目标，核对这轮要解决的问题，再用内核工作流程【1】把结论和必要依据讲清楚。

处理中追加【2】或【3】时，在进度说明中指出要补哪一处缺口。交付时对照开工说明，核对引导词带来的实际动作和结果。比如核对读到的目标怎样影响了本轮结论，或重构补上了哪一段缺失的解释。发现动作遗漏时，回到相应步骤补齐。 [Matt 演讲中的引导词检验](https://www.youtube.com/watch?v=UNzCG3lw6O0&t=743s) · [引导词原文](../skills/mattpocock/writing-great-skills/writing-great-skills.md#leading-words)

**当前问题的解答。** 先给结论。复杂问题按需交代读者要用的名词、问题、方案和依据。涉及流程时，说明输入如何变成输出，给一个具体用例供核对。

**目标进展。** 写本轮实际解决了什么，用正文、查证结果或验证结果说明进展。

**下一步主导。** 写下一件要做的事、它要解决的缺口和完成依据，更新到[主导栏目](../../UNDERSTANDING.md#leadership)。

<a id="write-back"></a>
## 重构后的内容怎么写回

当追问暴露了上一版答案里的断裂，用【2】重写受影响的那段解释。借用垂直切片的完成尺度，选一处影响判断的缺口，贯通问题、必要的术语与前提、依据和结论，再用一个具体用例核对。读者能凭这一段理解并检验当前判断时，就完成这一处。还有缺口会改变本轮判断时，再做下一处。 [交流内核【2】](../communication-core.md#part-2) · [Matt 的垂直切片原文](https://www.aihero.dev/skills-to-tickets)

【1】和重构可以产出以下内容。需要写回时，按内容的用途找它的正文。 [重构与内容维护原话](workflow.md#intent-reconstruction)

| 产物 | 写回位置 |
|---|---|
| 已澄清、后续会用的领域术语 | 走[领域词汇入口](../README.md#domain-lookup)，在词汇表维护定义和具体用例。 |
| 解释问题所需的公理、定理 | 放在回答这个问题的领域正文。公理交代出发前提，定理交代如何从前提和依据得到结论，并写清适用范围。 |
| 已定且难以逆转的取舍 | 按[ADR 原话](../关于内容维护.md#maintenance-principles)记录决定及其根据。问题域正文需要这个取舍时，直接引用决定的出处。 |
| 后续各轮会复用的协作要求、判断方法或流程 | 写到[控制面](../README.md#control-plane)里负责该规则的正文。 |

已有正文走[内容维护](../关于内容维护.md#maintain-content)，把新发现接回原处并按需修正前后内容。遇到缺少正文且需要独立回答的新问题，走[新内容入口](../关于新文件.md)。其他地方直接链接到该内容的出处。
