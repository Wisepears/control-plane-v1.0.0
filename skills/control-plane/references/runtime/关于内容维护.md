# 关于内容维护

<a id="maintenance-principles"></a>

＜!!＞
关于文件内容**维护**：**开闭原则**：
禁止项目内的任意种内容内核、含义重复（如文档间，文档内），面向用户和AI的沟通、知识同步类文件则专注于问题域。形成领域术语后写入根目录 `GLOSSARY.md`，每个术语附一个具体用例。形成难以逆转且存在取舍的设计决策、方案决策时写入 `ADR.md`，决策，方法只在本文件维护；
- 文件内的内容维护之节间布局：节间正交解耦可增量，节间逻辑通畅。节的内部内容解耦可增量，新增内容少重写已有部分。（可含有阅读所需本文件GLOSSARY，使用到已有通用GLOSSARY，预备的公理定理；足够回答问题的结论。可选：数据流转，测试用例，完整实例，边界，变更记录等治理边界等。）
- 文件内的内容维护之内容展示方式的一些小tips：
	- **比较和区分**：可以多使用表格，排版易读。
	- **证据与决策可分离**，读者能分清哪些是判断、哪些是支撑判断的材料。格式有组织且易读
	- **异常有出口**。 方向变更、失败条件、未决事项，边界独立一节有明确位置，不散落在正文。
- 文件间内容维护之文件组织结构：组织可扩展新增一类文档不改已有整体结构。（如新增日志、产出、报告类文件或是控制文档、素材文档等等）
＜/!!＞

＜!!＞
